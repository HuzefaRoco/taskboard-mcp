# Taskboard MCP

A multi-user taskboard backed by Postgres. Each user connects through OAuth;
every task operation is scoped to that user's ID. MCP uses Streamable HTTP at
`/mcp` only.

## Configuration

The application reads these five environment variables (or a local `.env` file):

| Variable | Purpose | Local value / default |
| --- | --- | --- |
| `DATABASE_URL` | SQLAlchemy Postgres connection URL | Compose supplies `postgresql+psycopg://taskboard:taskboard@db:5432/taskboard` inside the app container. |
| `PUBLIC_BASE_URL` | Externally reachable origin, without `/mcp` | `http://localhost:8000` locally; the ingress HTTPS origin in the cluster. |
| `SESSION_SECRET` | Secret used to sign browser sessions | Required; generate a random value and keep it private. |
| `ACCESS_TOKEN_TTL_SECONDS` | Access token lifetime in seconds | `3600` |
| `REFRESH_TOKEN_TTL_SECONDS` | Refresh token lifetime in seconds | `2592000` |

Do not commit `.env` or secrets. Compose overrides `DATABASE_URL` to use its `db`
service; the host URL in `.env.example` is for a separately reachable Postgres.
Compose does not publish the database port.

## Local Setup

Install Docker with Compose. Copy `.env.example` to `.env`, then replace
`SESSION_SECRET` with a value generated by:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Start the stack from this repository:

```bash
docker compose up --build
```

The app waits for Postgres, runs `alembic upgrade head`, and starts on port 8000.
In another terminal, create users using email/password pairs:

```bash
docker compose exec app python -m app.seed alice@example.com 'alice-password' bob@example.com 'bob-password'
```

The seed command hashes passwords and leaves existing users unchanged. Use your
own passwords. Open <http://localhost:8000/connect> and sign in with a seeded user.
The task list is at <http://localhost:8000/>.

The supplied Compose stack has no persistent Postgres volume. Removing the
database container loses its data; use persistent storage for a deployment.

## Connect ChatGPT

ChatGPT needs a publicly reachable HTTPS endpoint. The cluster ingress supplies
that public HTTPS URL and forwards requests to the app on port 8000. Set
`PUBLIC_BASE_URL` to the ingress origin, such as `https://tasks.example.com`, and
restart the app so OAuth metadata and browser session cookies use that origin.
Localhost alone is not reachable from ChatGPT.

1. Open ChatGPT's Plugins page and choose **+**, then **Add custom MCP server**.
2. Enter a name and the ingress URL with `/mcp`, such as `https://tasks.example.com/mcp`.
3. Choose **OAuth**. Use dynamic client registration; this app exposes `/register`.
4. Create and install the plugin, then connect your account. Sign in as a seeded
   user and approve consent for `tasks:read` and `tasks:write`.
5. Select the plugin in a conversation and ask it to list, add, or complete your tasks.

See the official [custom MCP server setup](https://developers.openai.com/api/docs/guides/custom-mcp-server)
and [OAuth authentication guide](https://developers.openai.com/plugins/build/auth).
Custom MCP server availability depends on your account and workspace settings.

## Tools And Website

| Tool | Scope | Behavior |
| --- | --- | --- |
| `add_task(title)` | `tasks:write` | Create an `open` task for the authenticated user. |
| `list_tasks(status)` | `tasks:read` | List that user's tasks; optionally filter by `open` or `completed`. |
| `complete_task(task_id)` | `tasks:write` | Mark that user's task `completed`. |

Task statuses are exactly `open` and `completed`. OAuth scopes are exactly
`tasks:read` and `tasks:write`. Another user's task cannot be listed or completed.

The website is read-only by design for tasks: it displays your tasks and filters
them, but has no route to create, complete, or delete a task. It also supports
login, OAuth consent, connection status, and disconnecting your account.
Disconnect revokes your OAuth tokens; reconnect through OAuth to use MCP again.

## Tests

Use Python 3.13 and install the existing dependencies after activating a virtual
environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate with `.venv\Scripts\Activate.ps1` instead. Set
`TEST_DATABASE_URL` to a dedicated, reachable Postgres test database and set
`PUBLIC_BASE_URL` and `SESSION_SECRET`. For example, in PowerShell:

```powershell
$env:TEST_DATABASE_URL = 'postgresql+psycopg://taskboard:taskboard@127.0.0.1:5432/taskboard_test'
$env:PUBLIC_BASE_URL = 'https://tasks.example.com'
$env:SESSION_SECRET = 'local-test-session-secret'
pytest -v
```

Tests run migrations and isolate each test with rolled-back transactions. They
never use SQLite. The isolation test registers a connector, signs in two users,
approves consent, exchanges PKCE codes, and verifies isolation through `/mcp`.
